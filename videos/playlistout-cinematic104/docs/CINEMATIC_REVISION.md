# Cinematic Journey V2 · 导演剪辑、运动与节拍核查

## V1 的实际问题

上一版是 13 个 × 8 秒的独立章节，固定采用“左标题 / 右插画”构图，只在章节末尾用 0.65 秒线性擦除。虽然单个镜头有动画，但场景与场景没有共享空间，观看时有明显的 PPT 翻页感。

## V2 的结构性解决方案

1. **一条真实的长卷世界坐标**：13 个章节的场景排布在同一个 24,960 像素宽的世界中。相机的 `cameraDistance()` 计算连续世界位移，不再清空画面再加载下一页。
2. **预先进入的镜头**：每个边界有 2.5 秒连续移动窗口（从边界前 1.25 秒到后 1.25 秒）。旧场景和新场景在同一个合成空间同时存在，不靠透明度直接淡掉。
3. **贯穿 104 秒的唯一主体**：黄色 `PLAYLIST PASSPORT` 票据，拥有可追踪的帧级坐标、颜色与纸张纹理。在场景交接时变大，物理遮挡镜头并携带下一个章节标签。
4. **四种节奏变奏**：票据在不同边界采取飞越、横向递送、翻卷、旋转推进的不同轨迹，不是同一个通用擦除预设重复 12 次。
5. **镜头呼吸 / Dolly**：静态展示阶段进行轻微、有边界约束的推进与平移，关键操作还会增加近景推镜（最多约 23%），并在近景中临时移走大标题，让观众看到更清楚的 UI；转场叠加最多约 2.5° 的摄影机旋转和 7% 的推进。
6. **物理联结与镜头引导**：底部虚线音乐轨道跨过场景边界，局部箭头和文件票据沿着轨迹移动。纸胶带、手绘强调、曲目标记、星光撞击都对应实际的复制、解析、导出、导入等叙事事件。
7. **真正的内部动作**：逐步输入、光标移位、按钮点击、列表展开、格式文件弹出、行高亮、批量归档、JSON 文件交接、CLI 打字与 API 数据流。元素变化发生在阅读自然节拍上，而不是为了每帧增加闪烁。
8. **120 BPM 精确卡点**：一拍 0.5 秒（15 帧），场景边界都在四小节节点。每次镜头推入从第 -2.5 拍开始，关键撞击在正拍，声音加入原创滑音 / 纸张 swoosh 与最后的轻触反馈。

## 自动 QA 与限制

- 逐帧输出 SVG，检查 3120 / 3120 帧存在、XML 解析成功、文件非空。
- 以 2 秒取样 + 各边界前后 + 每段中间的方式抽样 90 帧，生成 8 张 contact sheet。
- 额外从最终 MP4 提取关键帧，核对编码后的实际画面。最终视频必须为 104 秒、1920×1080、30fps、H.264 + AAC。
- 画面中文字从固定标题/操作区内排版，主角票据只在转场阶段允许覆盖 UI（模拟物理遮挡），静态展示阶段不会覆盖交互区。
- 本质上是音乐手账视觉语言制作的**动画演绎**，不是项目网页的屏幕录制。Remotion CLI 未在本环境验证，不能宣称 native Remotion 渲染通过。
