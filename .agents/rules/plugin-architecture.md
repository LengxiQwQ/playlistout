# Player Plugin Architecture & Naming Rules

When developing, refactoring, building, or publishing player plugins (under `plugins/` or `web/public/plugins/`), the agent MUST adhere to the following invariants:

## Mandatory Invariants:

1. **Namespace Isolation**:
   - Each player integration MUST have its own isolated directory: `plugins/<player-id>/` (e.g., `plugins/musicfree/`).
   - Root configuration files or scripts MUST NOT hardcode any single player's artifacts.

2. **File Naming & Link Safety (Hyphens Only)**:
   - Plugin filename format: `把你的歌单带走-PlaylistOut.js`.
   - **CRITICAL**: Use a hyphen (`-`), NEVER parentheses in file names or URLs (e.g., avoid `(PlaylistOut).js`).
   - Parentheses break Markdown link syntax `[text](url)` and get corrupted or truncated by mobile clipboards and social sharing.

3. **Platform Display Name & Backward Compatibility**:
   - Plugin runtime metadata display name: `platform: "把你的歌单带走 (PlaylistOut)"`.
   - Internal helper `isSelfPlatform(name)` MUST support both the legacy `"PlaylistOut"` and the standardized `"把你的歌单带走 (PlaylistOut)"`.

4. **URL Hosting Structure**:
   - Direct plugin file: `https://playlistout.lengxiqwq.com/plugins/<player-id>/把你的歌单带走-PlaylistOut.js`
   - Dedicated subscription source: `https://playlistout.lengxiqwq.com/plugins/<player-id>/plugins.json`
   - Global ecosystem manifest: `https://playlistout.lengxiqwq.com/plugins/index.json` (auto-generated by `scripts/build-plugins.js`)

5. **Universal Discovery & Testing**:
   - All plugins must provide `package.json`, `scripts/build.js`, and `test/test-runner.js`.
   - The root commands `npm run build:plugins` and `npm run test:plugins` automatically discover and execute all plugins.
   - Do NOT bypass `scripts/test-plugins.js` in `scripts/ci-gate.js`.

6. **Frontend Decoupling**:
   - `web/src/components/ecosystem/PluginEcosystem.tsx` must drive player cards and URLs dynamically via config objects (`integration.pluginUrl`). Never reintroduce hardcoded player constants.
